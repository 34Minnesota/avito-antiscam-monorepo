# Кейс 5: «Антискам тренажер»

## О проекте

Интерактивный тренажёр, который учит распознавать мошеннические схемы во время диалога на платформе Авито.

Пользователь оказывается внутри переписки: он видит карточку товара, профиль собеседника и диалог, который развивается как настоящий.
На каждой развилке нужно выбрать, что ответить, — и сразу получить последствие выбора и объяснение, почему он безопасен или опасен.

Прохождение можно вести за покупателя и за продавца: схемы обмана у них разные.

Ключевые возможности:

- **Сценарии от лица обеих сторон** — каталог тренировочных сценариев для покупателей и продавцов;
- **Немедленная обратная связь** — после каждого выбора видно реакцию собеседника и разбор, а не только итог в конце;
- **Последствия вместо очков** — рискованный выбор продолжает диалог и засчитывается как пропущенный признак, фатальный обрывает сценарий провальной концовкой;
- **Разбор в конце** — балл, список пропущенных признаков мошенничества с пояснениями и вывод;
- **Видимый прогресс** — статистика по сценариям, сравнение ролей, динамика относительно прошлых попыток и рекомендации, что пройти дальше;
- **Прокачка профиля** — опыт за завершённые и безопасно пройденные сценарии, за улучшение прошлого результата и за безупречные прохождения; накопленный XP поднимает уровень, а отдельные вехи открывают достижения.

## Запуск

Клонируйте репозиторий и перейдите в него:

```bash
git clone https://github.com/34Minnesota/avito-antiscam-monorepo.git
cd avito-antiscam-monorepo
```

Создайте локальный файл конфигурации:

```bash
cp .env.example .env
```

Запустите базу данных, примените миграции и поднимите API:

```bash
make deploy
```

После запуска:

- Frontend: [http://localhost:3000](http://localhost:3000)
- API: [http://localhost:8080](http://localhost:8080);
- health-check: [http://localhost:8080/healthz](http://localhost:8080/healthz);
- Swagger UI: [http://localhost:8080/swagger/index.html](http://localhost:8080/swagger/index.html).

## Технологии

### Frontend

| | |
|---|---|
| React 18 + TypeScript 5 | UI и статическая типизация |
| Redux Toolkit + RTK Query | стейт-менеджмент и работа с HTTP: кеширование, инвалидация по тегам, единая точка для заголовка `X-Session-ID` |
| React Router 6 | маршрутизация SPA |
| Vite 5 | сборка и dev-сервер |
| Sass (CSS Modules) | стили с изоляцией по компонентам |
| ESLint + Prettier | статический анализ и форматирование |
| Vitest + Testing Library | модульные и компонентные тесты |
| Playwright | e2e-тесты |

### Backend

| | |
|---|---|
| Go 1.26 | язык сервиса |
| Gin | HTTP-роутинг и middleware |
| pgx/v5 | драйвер PostgreSQL и пул соединений |
| zap | структурированное логирование |
| swaggo | генерация OpenAPI-документации из аннотаций |
| bcrypt | хеширование паролей |

Слои: `transport → services → storage`, доменные модели в `domain/models`.
Интерфейсы репозиториев объявлены у потребителя — сервисы не зависят от конкретного хранилища.

### База данных: PostgreSQL 16

Выбор обоснован тем, как устроены данные тренажёра:

- **Реляционная целостность.** Попытки ссылаются на пользователей и сценарии, шаги — на попытки.
- **Сложные инварианты на уровне схемы.**
- **JSONB для контента.** Сценарий — дерево из сцен, вариантов, реакций и концовок. В JSONB он лежит одним документом.
- **Транзакции.**

Документные и key-value хранилища не подошли: они дают гибкость JSONB, но не дают внешних ключей, частичных уникальных индексов и транзакций, на которых здесь держится корректность.

### Конфигурация линтера для бэкенда

`.golangci.yaml` в корне проекта, формат конфигурации версии 2. Включено 22 линтера; ниже — зачем взяты неочевидные.

**Корректность:** `govet`, `staticcheck`, `ineffassign`, `unused`, `errcheck` (с `check-type-assertions` и `check-blank` — необработанной считается и ошибка, присвоенная в `_`), `errorlint` (ловит сравнение ошибок без `errors.Is`), `bodyclose` (незакрытые тела HTTP-ответов), `makezero`.

**Контекст и время:** `contextcheck`, `fatcontext` (контекст, случайно созданный в цикле), `durationcheck`, `noctx` (запросы без контекста).

**Безопасность:** `gosec` с порогом `medium/medium`, `nosprintfhostport`.

**Сложность:** `gocyclo` и `gocognit` с порогом 15, `maintidx` — держат функции разбираемыми.

**Производительность:** `prealloc`, `perfsprint`, `intrange`, `copyloopvar`.

**Тексты:** `misspell` — опечатки в комментариях и строковых литералах.

Форматирование — `gofmt` с `simplify` и `goimports`. Лимиты `max-issues-per-linter` и `max-same-issues` сняты, чтобы линтер показывал все замечания, а не первые несколько.

Запуск: `make lint` (с автоисправлением). В CI линтер и тесты гоняются отдельными джобами — `.github/workflows/`.

## Структура проекта

```text
├── backend/
│   ├── cmd/antiscam/         # точка входа
│   ├── internal/
│   │   ├── domain/
│   │   │   ├── models/       # доменные модели
│   │   │   └── errors/       # доменные ошибки
│   │   ├── services/         # бизнес-логика
│   │   │   ├── training/     # движок прохождения сценариев, подсчёт итога
│   │   │   ├── progress/     # агрегация прогресса и рекомендации
│   │   │   ├── auth/         # сессии и вход
│   │   │   └── users/        # регистрация и профиль
│   │   ├── storage/postgres/ # репозитории на pgx, по пакету на модуль
│   │   ├── transport/http/   # хендлеры, middleware, DTO
│   │   └── logger/           # настройка zap
│   ├── migrations/           # миграции бд
│   ├── docs/                 # сгенерированный OpenAPI + JSON-сценарии
│   └── Dockerfile
├── frontend/
│   ├── src/
│   │   ├── app/              # провайдеры, роутинг, глобальные стили
│   │   ├── pages/            # экраны: вход, каталог, тренировка, итог
│   │   ├── widgets/          # составные блоки: чат, разбор, прогресс
│   │   ├── features/         # пользовательские сценарии: прохождение, выход
│   │   ├── entities/         # предметные сущности: сценарий, прогресс, юзер
│   │   └── shared/           # API-клиент, UI-kit, утилиты, контракты
│   ├── e2e/                  # Playwright
│   ├── nginx.conf            # раздача SPA и проксирование /v1 на backend
│   └── Dockerfile
├── docs/                     # описание кейса
├── .golangci.yaml            # конфигурация линтера Go
├── docker-compose.yaml       # postgres, миграции, backend, frontend
└── Makefile                  # deploy, тесты, линтер, миграции, swagger
```
